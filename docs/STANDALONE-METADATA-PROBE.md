# Standalone metadata probe

This route proposes one new, stopped, directly connected Outlook flow. It does not deploy the recruitment analysis, approve its design or tasks, read messages, generate a report, or authorize sending email. The existing business runner remains solution-aware until its separate standalone implementation is accepted.

The normal host exposes `/api/repos/:repo/standalone-probe` and its `review` and `execute` POST routes. The independent assigned QA worker uses `delivery_record` action `standalone_probe` to inspect, page through every complete source capsule and control, and persist its decision. The manager cannot record QA approval. Execution requires the exact current proposal hash, unexpired approval of all five controls, unchanged record, target, capability configuration, source and live standard policy.

The fixed definition contains two literal folder-metadata GETs, including one deliberate missing-folder request. The manual trigger carries only the probe kind and correlation UUID. It contains no message route, send action, schedule or arbitrary input definition. Native outputs are retained in the existing protected Windows leaf before semantic review; unexpected wrappers are retained rather than normalized into success. A completed technical receipt expressly withholds native semantic and business acceptance.

The original failed solution-membership attempt remains quarantined. Its exact index, ten journal files, resource lease, expired original window and dead original process are checked without repair or reclamation. Current owner, stopped state, empty caller-visible run history and the exact original counter definition are also required before creating the replacement. These observations do not settle the original provider operation. Independent review must assess isolation; neither missing named membership nor process death grants replay authority.

The replacement has a different fixed name, direct existing connection, lease namespace, stable scope, journal and approval storage. It never creates a publisher, solution or connection reference. Current Owner permission is read through the existing provider API; creator metadata is insufficient. Classic flows may lack a Dataverse workflow row. Dataverse-backed flows require bounded actual memberships containing only unmanaged Active/Default platform layers. Unknown metadata, named membership, logical references or any original-resource identity overlap fail closed.

The local compatibility adapter is reproduced from the exact pinned installed SDK into a separate hash-named file. The cached plugin is unchanged. The patch removes create-time reference enrichment, rejects duplicate override and fails closed when duplicate discovery fails. Its additional owner tool is read-only and grants no privileges. Inspection never writes or repairs the candidate. A read-only handshake/preflight is not creation, execution or deployment evidence.

The original 120-second attempt, 90-second new-work cutoff, 64 admitted-call ceiling, bounded captures and 16-entry/128-KiB-per-entry/384-KiB-aggregate source limits remain. Capsules retain complete original file text and hashes; no excerpts or source omissions are used to fit these limits. A failed or uncertain replacement preserves its own exclusive intent and lease, alongside the untouched original hold. Changing the record or proposal does not re-arm replacement creation. There is no cancellation, automatic replay, lease clearing or recovery endpoint.

Before business deployment, separately complete the standalone business manifest/runner, protected source capture and semantic checker, rule-quality and fault cases, independent design/task acceptance, real dry runs, exact accepted report binding, persistent single-send protection and native Inbox receipt verification. Technical metadata success supplies no credit for these gates.
