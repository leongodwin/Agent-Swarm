# Cloud-flow adapter connection guards

The connection path now verifies cancellation/closure after handshake and every discovery response, rather than trusting a provider to obey its signal. Repeated discovery cursors fail immediately; unique continuation chains still have the existing twenty-page cap. Every required management tool must be discovered before returning the adapter. A late page after cancellation cannot return a usable connection.

Tool results are denied after cancellation or close begins. Response text is bounded by UTF-8 bytes, not JavaScript character count, so multi-byte content cannot exceed the declared 2 MiB limit unnoticed. Malformed JSON returns a content-free diagnostic instead of exposing a parser excerpt from the provider response. Structured failure flags remain denied. These checks do not replace typed target/identity/binding validation or mutation-journal reconciliation.

The new connection integration tests exercise the actual adapter factory with temporary runtime paths and simulated MCP client/transport interfaces. They cover paged/missing/repeated/excess discovery, cancelled late pages, late tool responses, joined cleanup, structured/malformed failures, Unicode byte limits, response-canary withholding, retained connection/cleanup causes and cancelled/unavailable startup. The earlier owned native subprocess cleanup fixture remains separate proof of process-close behaviour. No real FlowAgent, authentication or tenant tool call is made by these connection fixtures.
