# Resource tenant identity for project target refresh

The PAC profile list exposes the selected account and organization URL, not the environment's tenant ID. Ordinary profile-list discovery continues to report unknown tenant metadata. The normal project-target refresh derives the resource tenant from the authenticated organization at that exact selected URL; it does not invent a tenant, copy an unrelated Azure account or read a requested tenant value from its caller.

Verification reads `pac auth list`, performs three fixed Dataverse identity GETs at the intended root (WhoAmI, RetrieveCurrentOrganization and the returned current system user), then rereads the PAC profile list. The authenticated organization and WhoAmI organization IDs must agree; the current system-user ID must equal WhoAmI, and the enabled human user's name must match the selected PAC account. Tenant/environment/organization and Entra identities must be well-formed. The final active profile index, user and URL must be unchanged. Missing/ambiguous identity, malformed/oversized JSON, changed profile generation, pending profile ownership, closed service or command failure prevents a result.

The resource tenant comes from RetrieveCurrentOrganization. This is distinct from a user's home-tenant metadata or proof that every provider uses the same token. The setting-only native client still separately validates its executing token, exact expected tenant/environment/organization/user/Entra identity and named privilege before an independently approved write. A discovery result never substitutes for that admission, connector mailbox binding, business licensing, effective policy, private-mail authority or deployment acceptance.

PAC's account-enrichment and token commands are not needed in this path. They were unreliable under the existing Windows command bound; removing unnecessary enrichment does not remove authenticated server identity checks. All five metadata commands retain the eight-second limit. No CLI, task, release, coverage or review deadline/threshold is enlarged. The reads create no login, consent, profile selection, setting/flow mutation or Dataverse business-flow action. Demo mode performs no native discovery.

The existing target endpoint retains idle/account/environment/expected-target guards and saves the actual resource tenant only after verification. Automatic assignment and merging stay disabled. Read ownership remains tracked through shutdown, and generation/ownership are rechecked after awaited commands. Complete administrative source capsules include the reader, native parsers and actual target-refresh callsites.

Validation covers the exact five-read sequence; genuine server-tenant discovery; wrong initial/final profiles; missing, malformed, oversized and inconsistent native identity; disabled/application users; unsafe URLs; command errors; profile drift/ownership revocation and shutdown; and normal target persistence/refusal. Local mocked tests are distinct from a successful normal app target refresh, and neither supplies a tenant-write, workflow or email receipt.
