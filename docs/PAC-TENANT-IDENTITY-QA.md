# Selected PAC tenant identity for project target refresh

The PAC profile list does not expose tenant IDs. Ordinary profile-list discovery continues to return unknown tenant metadata. Project target refresh now uses an explicit read-only verification method rather than copying an unrelated Azure account, a requested tenant value or an operator edit into saved state.

The method requires the intended account and environment to be selected already. It reads `pac auth list` and `pac auth who`, then performs three fixed Dataverse identity GETs at the exact selected organization: WhoAmI, RetrieveCurrentOrganization and the returned current system user. It rereads the PAC profile list before returning. The actual server tenant/environment/organization, enabled human user, Entra object ID and user name must match the selected PAC profile. This is identity metadata, never a Dataverse business-flow action. The final active profile index, user and URL must still match. Malformed, missing or duplicated identity fields, changed profile generation, closed service or native command failure prevent a result. It creates no login, consent, profile-selection or tenant mutation.

The normal project-target endpoint retains its existing idle/account/environment/expected-target guards. It persists the corroborated tenant through `refreshRepoTarget` and keeps automatic assignment and merging disabled. The exact administrative native client still independently checks executing token and server tenant/environment/organization/user/privilege before any separately approved setting operation. This discovery result is not business licensing, effective policy, private-mail authority or deployment acceptance.

No CLI, task, release or coverage timeout/threshold is enlarged. Native reads retain existing command bounds; a timeout yields no verified tenant. Read ownership remains tracked through shutdown and profile generation is rechecked after every awaited command. Demo mode performs no native discovery.

Validation covers the complete positive six-read sequence; mismatched accounts, targets, organization/environment IDs and final active profiles; duplicate/missing/malformed/oversized identity output; native read errors; profile drift and shutdown; and normal target persistence/refusal. Fixed administrative source capsules include this reader, its parser and the actual target-refresh callsites so subsequent independent review binds the implementation it relies on. Local mocked checks are not a real tenant-write or workflow success receipt.
